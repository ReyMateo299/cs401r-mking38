Line references below refer to those files. This is an instruction audit, not a grade for any student. **User decision:** where they conflict, follow the student handout.

The main 25/25/20/15/15-point task structure is present in both documents. The current handout explicitly asks for the five lifecycle rules, transaction-level deduplication, fixed feature cutoff, 16 Feature Store definitions, contract sections, and lineage edge labels. Those should **not** be treated as discrepancies. The handout also says the TA has no AWS account access and should grade committed code and logs after teardown (handout lines 349–364 and 757–790); the grading pipeline must make no live AWS calls.

**TA scoring direction for the regraded cohort:** Apply the older Task 2 rubric excerpt supplied by the TA, even where the current handout asks for saved verifier output. In that older rubric, T2.1 requires `aws glue get-table --database-name northstar_dev --name customers` to return a schema, but does not require committing its output. T2.2 concerns the transform assertions/results; T2.3 requires a Glue module and a clean apply creating the crawler and job; T2.4 requires `get-job-run` to return `SUCCEEDED`, but does not require committing the output. Therefore, missing `docs/lab2-verify-output.txt` alone is not a deduction on T2.1 or T2.4. By the TA's direction, apply the same no-saved-output rule to T3.4 for this regrade, while retaining deductions for explicit saved FAIL results. T2.3 does not deduct for a missing private connection or Terraform-managed script upload unless another applicable criterion covers it. Where no runtime output exists, record that the historical result was not independently confirmed offline rather than claiming a live result. The older T2.2 excerpt says "no duplicate `customer_id` rows," but this conflicts with the applicable handout's explicit transaction-level grain and `transaction_id` deduplication. Keep the handout's grain requirement; the solution notes say not to deduct for the obsolete "No duplicate customer_id rows" contract wording.

## Conflicting scoring instructions and adopted rule

These are conflicts rather than missing student requirements. The handout governs; potential secret matches and ambiguous evidence still require human verification.

| Issue | Conflict | Adopted handling |
|---|---|---|
| Committed secrets | The handout says committed secrets are an **automatic zero** (handout line 381). The TA guide says `.tfstate`/`.tfvars` or AWS keys in Git cost **5 points**, while its security protocol says award zero for Task 5 parameterization (guide lines 392–429). | A **confirmed committed secret** sets the whole assignment to **0/100**. A prohibited filename alone is a review flag, not proof that the file contains a secret. Check starter-kit/LocalStack false positives and never copy a secret value into feedback. |
| Teardown cap | The handout says missing evidence caps Task 1 at **half credit**, or 12.5/25 (handout line 790). The TA guide sets the cap to **12/25** (guide lines 299–309). | Use **12.5/25**. Read the destroy log on the default branch, since the handout explicitly places it after the submission tag (handout lines 366–381 and 784–790). |
| Function deductions exceed function points | The guide's deduction table says an out-of-range churn score costs 3 although `compute_churn_proxy` is worth 2; it says degenerate tiers cost 3 although `assign_loyalty_tier` is worth 2 (guide lines 186–211 and 392–414). The handout gives the five functions 10 points total without those 3-point penalties. | Use the guide's compatible 2/3/2/2/1 subdivision and cap a function's deduction at its own points. An out-of-range score or degenerate tier can each cost at most **2** within the corresponding function. |

## Evidence rule for implementation

Terraform/Python static analysis can show that a resource or computation was defined, but cannot prove that a Glue job succeeded, a crawler ran, a Feature Group received records, or AWS resources were destroyed. Use committed apply/verify/destroy logs as historical evidence and mark unsupported outcomes for review. Do not invoke AWS, run a submitted verifier, or require a live stack. The handout explicitly rejects AWS-console screenshots as a Lab 2 requirement (lines 349–364).
